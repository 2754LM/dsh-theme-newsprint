fix(packaging): declare dsh.client so the cordis client runner picks up lib/client.js

The 2.0.0 cordis-shim form was correct in spirit (no ctx.theme, no
dsh-client-ui-theme dependency, just inject one <style>) but
removed dsh.client from package.json entirely. That broke
activation: dshmarket's hot-mount path skips packages whose
package.json has no dsh.client field, and the official
@deepseek-ai/dsh-client-modules runtime also keys off dsh.client
to discover the package's exports['./client'] entry and load it.
With dsh.client missing, lib/client.js was never imported and
apply() never ran, so the style element was never injected.

inject is left empty on purpose: 1.0.3 had five specific
@deepseek-ai/* names that, while real in 0.1.5-rc.2, were stale
references in earlier 0.1.x where dsh-client-runtime still
existed; listing them reopens the crash class. Empty inject
keeps dshmarket's hot-mount path happy without referencing
specific client package names that may go stale again. The
client half itself does not import any @deepseek-ai/* runtime
(it only uses cordis's ctx.effect for teardown), so an empty
inject is sufficient.

Bump 2.0.0 -> 2.0.1.
